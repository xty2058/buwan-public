从场景推导出来的每一个值。

先有用户和场景，再有体验承诺和品牌原则，最后才是颜色、字号、间距和动效。本页把这条链路写清楚，并给出每个 Token 的用法和禁用规则。

暮光环境光 + 颗粒（P0）

背景不是色块，是光：杏色从左上、玫瑰从右侧、梅紫从底部晕开，再叠一层很细的胶片颗粒（--bw-aurora + --bw-texture-grain）。玻璃透出这层光，界面就有了“天将黑未黑”的温度。

这样用

  • 角色立绘是唯一的视觉主角
  • 记忆相关图标用烛金，其他图标继承文字色
  • 新增图标先进 icons.svg 并登记在本页

不要这样

  • 用 ✨ 星星代表 AI
  • 做通用的 AI 吉祥物
  • 混用填充图标和线性图标

正在输入：1600ms 匀速呼吸，不伪造打字延迟

遮罩 200ms 淡入，面板上浮 8 像素、320ms、缓出，没有回弹。按 Esc 或点遮罩也能关闭，焦点回到触发按钮。

这样用

  • 回复到了就显示，流式输出逐字出现
  • 记忆写入成功时只点亮一次
  • 系统开启“减弱动态效果”时，所有动画降到瞬时，循环动画改为静态

不要这样

  • 弹簧回弹、抖动、晃动
  • 为了“像真人”故意延迟显示回复
  • 付费成功放礼花、金光、全屏动画

#a11y

可访问性

玻璃和环境光很容易牺牲可读性，所以这里的规则比视觉规则优先。每个页面上线前按此清单逐条检查。

看得清

  • 文字与背景对比度 ≥ 4.5:1，深浅两套都实测（见 色彩 · 对比度实测）
  • 需要认真读的内容放在实底玻璃上
  • 颜色不单独表意：状态必须有图标和文字
  • 支持系统文字放大到 200% 不截断；聊天正文最小 16

点得到

  • 点击区 ≥ 44 × 44（--bw-size-tap）
  • 等权选项的尺寸和间距完全一致
  • 底部操作区预留安全区 env(safe-area-inset-bottom)

键盘可用

  • 每页第一个焦点是“跳到正文”
  • 焦点环 2px --bw-color-focus，偏移 3px，任何组件不得去掉
  • Tab 顺序与视觉顺序一致；弹窗打开时焦点进入，Esc 关闭并回到触发点
  • 单选组用原生 radio 或 aria-pressed / aria-current 标明选中

读屏能懂

  • 页面有 header / main / nav 地标，且只有一个 h1
  • 对话流 role="log"，新消息自动播报
  • Toast 用 aria-live：普通 status，出错 alert
  • 弹窗用原生 <dialog> + aria-labelledby
  • 纯图标按钮必须有 aria-label；输入框必须有关联标签

减少动态

components.css 里的 prefers-reduced-motion 规则会把所有动画和过渡压到瞬时；呼吸类循环动画改为静态半透明。
