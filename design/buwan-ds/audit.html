S1

发现角色与第一次开聊

达成
用户任务
一屏一个人，上下滑看下一个；看到合拍的，直接把替你写好的第一句发出去。
成功标准
打开即全屏人物，没有卡片和列表；底部黑色渐变上是名字、身份、标签和一个毛玻璃开场面板（情境 + 他的第一句）；主操作就是输入框，已替用户写好一句，发送即在首页原地开聊、免注册；底部顺序参考猫箱：开场 / 对话 → 名字与性格（固定）→ 输入框，实测名字行开聊前后位置不变（实测：不跳页，情境变成对话顶部系统行、他的第一句变成第一条气泡，回复先“正在输入”再逐字出现；旧消息上移淡出，可上滑翻看；滑到下一个人再滑回来，对话仍在；清空时只聚焦输入框）；换开场在原地轮换；整屏吸附上下滑（实测）；没有位置圆点、位置播报、说明小字和 AI 标识。
模板与组件
T5 沉浸全屏（宽屏居中，两侧同图模糊，实测随角色切换）· Spotlight（含 is-chatting）· Thread(on-image) · Typing · Tag(on-image) · OpeningPanel · Starter · IconButton · Tabbar(solid，纯黑)
四关键词
同一个人：立绘就是这个人，开场原话即人设。由你决定：替你写的话可以直接发、可以改、可以换开场或滑走。接得上：发出的第一句就是长期会话的第一句。记得对：首聊没有记忆，不做虚假承诺。
可访问性
唯一 h1（视觉隐藏）；每屏 article 以名字命名；图片有具体 alt；滑动区可聚焦，↑↓ / PageUp / PageDown 翻屏；输入框有隐藏 label，发送按钮写明“开始和某某聊”；不播报位置。
S2

日常聊天会话

达成
用户任务
接上话题、发消息；回复出错时续写或重写；对角色的提议做自己的选择。
成功标准
发送后先出现“正在输入”，再逐字出回复（实测通过，结束后流式状态正确清除）；出错回复原地标“没生成完 · 本条不扣”，续写 / 重写一步完成；关系提问给等权选项；聊天流里没有任何推广，额度只在输入框上方。
模板与组件
T2 App 分栏（≥1024 右侧回顾与记忆）· Topbar · Continuity · Thread · Message · Bubble（error / streaming / invalidated）· MemoryChip · Retry · ChoiceGroup · Typing · SystemLine · QuotaHint · Composer · Sheet
四关键词
同一个人：角色气泡样式与语气恒定。记得对：“想起了：周四复试”可点开、可纠正。接得上：顶栏常驻“已存档 · 记得 23 件事”。由你决定：等权选择组，AI 不代答。
可访问性
对话流 role=log + aria-live；流式输出期间 aria-busy，读完一次性播报；输入框隐藏标签；Enter 发送、Shift+Enter 换行；原生 dialog，Esc 关闭并归还焦点。
S3

隔天回归与记忆连续性

达成
用户任务
一眼看到上次聊到哪、有哪些未完成的约定；确认他还是那个人；直接接着聊。
成功标准
首屏是回顾卡（内容、约定“周四 7:30 叫醒你 · 还没到”、关系阶段）；主动说明“引擎已更新，人设和 23 件事都没变”并可展开人设锚点；问候引用具体记忆、不施压；输入框始终可用、没有弹窗挡路；存档时间、导出、下线前 30 天通知均可见。
模板与组件
T2 App 分栏（≥1024 右侧共同经历时间线，移动端用底部面板）· Recap · Promise · Stage · Notice（memory / info）· Checklist(memory) · Thread · MemoryChip · Timeline · Continuity · Composer
四关键词
同一个人：人设锚点清单。记得对：记忆标签可查可纠正。接得上：回顾、约定、时间线、存档与导出。由你决定：关系阶段只显示不自动推进。
可访问性
阶段为有序列表 + aria-current=step；人设锚点用原生 details；“接着聊”把焦点移到输入框。
S4

剧情分支、关系推进与记忆纠正

达成
用户任务
回应或拒绝邀约；从这一句开支线并能切回；调整节奏或推进关系；纠正或删除记错的事。
成功标准
三个邀约选项等宽同色阶，拒绝后系统行说明“不会影响你们的关系”；分岔前说明原线保留；关系只由用户推进且需二次确认；纠正后四处同时反馈（实测：面板自动聚焦并预填 → 提交后记忆条目显示旧值、标签点亮为“复试在周四”、角色回复“记下了，是周四”、提示“已记住…之后按这个来”）。
模板与组件
T2 App 分栏 · ChoiceGroup · BranchPoint · BranchSwitcher · Branch · Stage · Segmented（原生 fieldset）· MemoryList · MemoryItem · Correction · Field · Input · Modal · Sheet · Timeline · Toast
四关键词
同一个人：拒绝或放慢后语气不变。记得对：可查、可改、可删，改动即时生效并留痕。接得上：分岔保留原线。由你决定：选项等权、阶段只由用户推进、每次改动有确认和反馈。
可访问性
选择组 aria-pressed；节奏用 fieldset + legend；纠正错误用 role=alert 并通过 aria-describedby 关联；弹窗关闭归还焦点。
S5

额度与付费决策

达成
用户任务
弄清为什么停了、何时恢复；看懂怎么扣；在“等明天 / 加油包 / 月卡”间决定；核对明细，确认或放弃支付。
成功标准
第一屏顺序固定：额度现状 → 扣费规则 → 三个等权选项（默认免费）→ 随选择变化的主按钮（实测：“好，明天见”→“订阅 ¥18/月”）；确认弹窗重列金额、周期、下次扣费日、退订方式，按钮等权；明细 7 行含两行“未扣费”；没有倒计时、红色警告或角色催付。
模板与组件
T1 App 单列 · Quota · Meter（is-low，中性色）· Continuity · Checklist · Plan（原生 fieldset + radio）· Button · Notice · Table · Tag · Modal · Toast
四关键词
同一个人：付费只用系统声部，角色不出场。记得对：明细逐条可查、合计可核对。接得上：额度用完也保存进度，付费后回到对话。由你决定：免费与付费等权、默认免费、支付前二次确认、退订同屏。
可访问性
原生 progress 带标签；额度文案 aria-live；套餐为真实 radio，方向键可切换；表格有 caption、th scope、tfoot。

#run

维护规则

新增样式的流程

  • 先在 tokens.css 加 Token（标 @principle / @scene）
  • 再在 components.css 或 layout.css 登记 class
  • 在 components.html 补用途、适用、不适用、状态、代码
  • 最后才在页面里使用，并跑一次 audit

不要

  • 在页面里写 style 属性或 <style>
  • 在组件 CSS 里写颜色或 px 字面量
  • 为了一个页面临时造组件变体
  • 跳过 audit 直接合并
