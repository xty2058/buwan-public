组件与状态

每个组件按同一模板书写：用途 → 适用 / 不适用场景 → 变体 → 七种状态 → 尺寸与间距 → 可访问性 → 代码 → 使用 / 禁用规则。检索：组件名、类名（如 .bw-memory-chip）、原则编号（P0–P6）或场景编号（S1–S5）都能直达。

状态的静态表现

hover / active / focus 在文档中用 .is-hover .is-pressed .is-focus 静态展示，与真实伪类共用同一条样式规则；产品页面只依赖真实交互，不手写这三个类。

#button

按钮

按钮只表达“用户要做的事”。一屏最多一个主按钮；接受与拒绝、订阅与退订必须同样可见。

按钮 Button

.bw-btnP2P4S1S5
用途
触发一个明确动作：开始聊、订阅、保存更正、从这里分岔。
适用场景
S4 关系推进确认；S5“订阅月卡 · ¥18/月”与“先不了”；S4 纠正面板的“保存更正”。
不适用场景
关系选项（用 ChoiceGroup 的 --choice，保证等权）；页面跳转的文字链接（用 a）；聊天流内的推广（禁止）。

  • 加载中保留文字并加 aria-busy="true"，屏幕阅读器不会丢失上下文。
  • 主按钮文字 --bw-color-on-accent 在渐变深端上 7.0:1。

代码

<button class="bw-btn bw-btn--secondary" type="button">换个开场</button>
<button class="bw-btn bw-btn--primary is-loading" type="button" aria-busy="true">正在订阅</button>

这样用

  • 一屏只放一个 --primary，其他用 --secondary / --ghost。
  • “先不了”“退订”与主按钮放在同一屏、同一视线。
  • 加载、出错时文案说清结果：“支付没完成，没有扣钱”。

不要这样

  • 用 primary + 灰色小字链接表达“接受 / 拒绝”（违反 P4）。
  • 付费按钮用 --danger 或红色制造紧迫感。
  • 按钮文案借角色口吻：“他在等你，快充值”。
